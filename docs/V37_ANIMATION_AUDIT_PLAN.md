## 3. 本阶段明确的动作要求

| 状态 | 画面与动作 | 保持与退出 |
| --- | --- | --- |
| 待机/休息 | 轻微呼吸，重心平稳，眼睛与发梢有克制的缓动 | 无工作和待回答事项时循环 |
| 浇黄瓜 | 微侧身、双脚并拢、双手共同握壶；长方体花盆的可见面与人物侧身一致；2–3 根黄瓜 | 待机行为；新工作或询问到达时平稳收动作并退出 |
| 工作 | 双腿微微分开、双手略用力；较浅金色光带在双眼内部持续向下流动 | 状态保持直到询问、结束或中断；气泡消失不结束动作 |
| 疑惑/询问 | 脸转向屏幕左侧，独立双眼同步位移并产生近远透视差；图二经典大眼表情；头部右上方弹出较大圆润问号 | 问题有效且未回答时保持；提交成功或请求取消/失效后退出 |
| 被抓住 | 后背衣服被提起的受力点；躯干上提，头发、手脚滞后并轻微挣扎 | 拖动期间显示，释放落地后恢复当前真实状态 |
| 形态转场 | Q 版转身，中间展示图三华丽正常版，完成立即回 Q 版 | 一次性动作；不把华丽版设成日常形态 |
| 轻点护脸 | 沿用已确定的 >< 眼、短手护脸 | 短暂覆盖，结束恢复底层状态 |
| 完成气泡 | 文案原样为“结束了......” | 触发语义待确认；错误/中断不伪报完成 |

推荐形态转场入口为右键菜单“转身变换”，避免与单击护脸、拖动冲突。此项属于可调整的界面实现建议。

## 4. 分层与运动方法

采用平滑 2D 分层、关键姿势和透视变形的方式实现立体感。

Krita 负责新模型拆层、遮挡区域补画、侧脸/侧身/背向关键姿势、手部受力和道具透视；Aseprite 负责分层时间轴、动作标签、时长与循环检查、透明动画资源导出。两种格式均实际打开/导出复核后交付，不将合成单层文件称为完整可动源稿。

最少独立部件：
- 后发、左侧发、右侧发、刘海/前发、发夹；
- 无眼脸底；
- 左眼、右眼（询问/闭眼/触碰为替换组，流光有各自遮罩）；
- 身体/裙摆、衣领/领结；
- 左臂与左手、右臂与右手，左右分别可动；
- 左腿/脚、右腿/脚；
- 水壶、水流、花盆、黄瓜；
- 问号和必要的转场遮挡层。

通过前后层次、局部位移、旋转、远侧缩短、动作起止缓动和发梢滞后来表达体积。侧身和转身需补画对应视角，不能只把正面整图横向压扁。

动画设计目标为 60 FPS 播放，验收要求正常目标电脑与默认大小下至少 30 FPS；关键绘制帧与连续插值配合。不能仅把旧帧重复填充或修改 FPS 标签视为达标。Aseprite 的整数毫秒时长需维持正确总时长。单独记录实际帧间隔、长帧、内存占用和默认尺寸下的视觉结果，减少动态效果设置另行保留。

## 5. 状态与会话衔接

建议基础链：启动核对 → 待机 → 收到用户指令/工作事件 → 工作 → 有效问题 → 等待 → 成功提交回答 → 恢复工作 → 完成或中断 → 待机。

- Codex 状态是底层状态；抓取、护脸、转场是短暂显示动作，不覆盖真实任务状态。
- 等待期间收到无关工具事件或普通 Stop，不丢失问题。
- 回答必须绑定会话、回合和问题 ID；过期、重复、取消的请求不能错误恢复任务。
- 多会话按“有效待回答问题 > 正在工作 > 待机”汇总，同时保留来源。
- 重连先核对请求与任务是否仍然有效；旧问题不能只凭历史文件假装还能提交。
- 问号退出以回答被正确接收/取消为准，不能只在用户点发送时提前消失。
- 形态转场期间如有急需用户处理的问题，返回 Q 版询问状态。
- 默认可见主体最大边继续以约 190–200 物理像素为目标，按显示器 DPI 换算，支持用户缩放；动作道具保留必要余量，避免裁切。旧 164 CSS px 设置只对旧模型和特定缩放成立，应重新实测。
- 桌宠感知的是已接入会话发来的事件，不代表自动读取所有 Codex 对话、共享所有指令或取得全部运行权限。

官方资料：Hooks 有覆盖范围限制；App Server 提供 thread/turn/item 事件与用户输入请求/响应，但另起 App Server 不等于能接管正在 Codex 桌面端等待的请求。
- https://learn.chatgpt.com/docs/hooks
- https://learn.chatgpt.com/docs/app-server

本地 Codex CLI 为 0.155.0-alpha.16.4，帮助中提供 app-server 及版本对应协议导出。实际双向接入时应以本机协议为准。
