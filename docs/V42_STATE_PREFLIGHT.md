# V42 状态发布前审计

审计日期：2026-09-28。本文仅记录公开可复现的事件结构、相对源码路径和验证结果；不包含真实对话标识、问题答案、用户目录或凭据。

## 状态依据

主要实现位于 `electron/codex-lifecycle.ts`、`shared/activity.ts` 和 `electron/main.ts`。

状态以实际结构化事件为依据。日志修改时间只决定读取顺序，轮询间隔只决定观察频率。长任务不会因为经过一定时间而自动结束。

| 场景 | 结构化依据 | 预期结果 |
| --- | --- | --- |
| 开始工作 | `event_msg/task_started`，有效 `turn_id` 和时间戳 | 对应主会话进入 `working` |
| 单项目 | 工作中的主会话只有一个规范化目录 | 普通 WORK |
| 多项目 | 工作中的主会话有两个或更多不同目录 | 全力 WORK |
| 暂停、停止 | 对应轮次的 `event_msg/turn_aborted` | 对应会话回到 `idle`，其他会话继续 |
| 恢复 | 新轮次的真实 `task_started` | 新轮次进入 `working` |
| 正常轮次结束 | 对应轮次的 `event_msg/task_complete` | 回到 `idle`；真实未回答的问题继续保持 `asking` |
| 完成或限额错误 | 对应轮次的 `task_complete` 带 `error` | 映射为中断，结束对应工作状态 |
| 发布问题 | 原生询问调用；异步询问还要求成功的 `accepted:true` 回执 | 进入 `asking`，回执本身不算回答 |
| 接收异步回答 | 原生回复封装中的工具名、调用标识、问题索引和轮次均匹配 | 同一轮次所有待回答问题均完成后恢复工作 |
| 已结束轮次收到回答 | 已关联的问题回复 | 清除提醒，保持 `idle` |
| 切换项目目录 | 当前轮次的 `turn_context.cwd` | 更新目录和项目计数，保留当前工作或等待状态 |
| 应用重启 | 验证 `session_meta` 身份，并重放实际轮次开始及后续记录 | 从日志恢复；不靠文件名或日志年龄推断工作 |
| 子代理 | 原生元数据确认子代理身份，或 hook 明确提供子代理标志 | 不参与主会话的 WORK 和项目计数 |

同一目录的多个聊天只计一个项目。Windows 驱动器和 UNC 路径统一大小写及分隔符，解析 `.`、`..`；POSIX 路径保留大小写区别。

## 本次复现并修复的问题

1. 延迟到达的旧 hook 开始事件可以覆盖更晚的原生轮次。现在原生轮次按原生开始时间排序，hook 的接收时间不能取代已验证的原生身份。
2. 异步问题发布失败后，hook 提前建立的等待状态可能永久保留。失败回执现在解除对应等待；原生跟踪建立后，问题状态及通知由关联的原生记录管理。
3. 无调用身份的 hook 问题完成事件可以提前清除另一个仍未回答的问题。原生跟踪要求全部关联调用及问题索引完成；迟到的 hook 问题事件不改变该状态。
4. 重复开始事件可以覆盖同轮次的真实等待状态。匹配已验证轮次的重复 hook 开始只补充允许的元数据。
5. 没有轮次身份的 hook 停止事件可以结束当前原生任务。已由原生记录确认的任务要求匹配的结束证据。
6. 原生目录上下文被忽略，重启和无 hook 的目录切换会沿用最初目录。现在当前轮次的上下文更新实际项目身份，并优先于迟到的旧 hook 目录。
7. 目录上下文被误当作工具继续执行，可以解除批准等待。上下文现在仅更新元数据；工具继续事件仍可解除已有的批准等待。
8. 元数据缓存保留了完整指令内容。现在只缓存会话身份、目录及主/子代理分类，并清除已删除日志对应的缓存。

局部 hook 实现 `plugins/liquid-glass-pet/hooks/notify.mjs` 保留明确的子代理标志，主进程接受该标志。原生确认的子代理身份不会被后续 hook 覆盖。此次审计没有修改正在安装使用的插件缓存。

## 已知边界

- 崩溃、断电或日志停止追加而没有结构化结束记录时，不能仅靠静默时间证明任务已结束。保留最后验证到的状态。
- 独立错误消息或工具输出中出现限额文字，不足以结束一个轮次。未见到的错误事件格式没有推测性映射。
- 冷启动自动发现检查最近 32 个日志候选，已保存的会话仍会被跟踪。未保存且不在该集合中的静默旧日志，须等待后续追加后才能被自动发现。
- 大型日志按批次逆向定位真实开始记录并顺序读取；恢复延迟受日志体积影响。元数据首行读取上限为 16 MiB。
- 已发现主会话的观察集合会随使用增长。没有明确结束或归档依据的状态不按年龄删除；此次优化缩减了缓存内容，没有新增按时间清理状态的规则。

上述结构测试与日志抽样使用独立或只读环境，未主动触发真实限额。最终发布包检查、应用重启与运行核查见 `V42_RELEASE_PREFLIGHT.md`。
