# 点击显示与举牌节奏修复（2026-10-14）

## 录屏问题与原因

用户录屏为 2560×1440、59.94 FPS。仅截取宠物区域复核：普通左键操作在 1.802、10.427 和 11.578 秒出现约 111×112 像素的单帧右下偏移及矩形裁切；举牌及拖拽切换还有 1–2 帧完全透明。

实际 Electron 基线复现了空帧。普通 512×512、举牌 768×768、拖拽 1024×768 的公开 Canvas 切换会清空画布，DOM 布局和原生透明窗口尺寸又通过 IPC 异步调整，帧间呈现不同步。512→1024×768 的局部原点变化为 256 像素，乘原显示比例约 0.434 后就是录屏中的 111 像素偏移。布局改变造成的 client 坐标变化还会进入旧拖拽累计距离。

## 修改

- `renderer/three-rig.ts`：Q 版公开 Canvas 固定 1024×768；离屏 WebGL 仍按原动作需要使用 512×512、768×768 或 1024×768。先绘制完整离屏画面，再清空和拷贝到公开画布。无实际尺寸变化时不重新设置 Canvas 尺寸。
- `renderer/main.ts`：固定这些动作共用的原生显示区与气泡预留空间，维持原模型像素密度和脚底锚点。视线与绕圈仍按原 512 像素角色范围归一化；拖拽距离只累计真实屏幕坐标变化。
- `electron/main.ts`：保存脚底世界位置以适应升级后的布局；屏幕边缘可见内容增长时用短暂平滑移动将其放入屏幕，无需切换窗口尺寸。真实用户拖拽优先。
- `renderer/v41-review.ts`：预览尺寸与新公开画布一致。
- `shared/quota-board-motion.ts`：保留原动作曲线，统一以 `6.2 / 3.8` 倍推进；完整举牌约 3.8 秒，进入、保持、淡出与双手恢复同步加速。动作进入/退出的姿态插值也按该倍数缩短。

额度来源、普通/超级工作识别、托盘设置、音频、模型和美术源稿均保持原样；新构建与安装前归档逐文件确认 30 份美术、音频、字体及样式一致，preload 字节一致。
