# 本机提醒状态修复记录（2026-10-06）

## 当前结果

已更新并重启本机 Deskfolk，包版本仍为 0.1.0。本次未提交、推送或更新 GitHub Release。

已解决的错误链路：

1. `PermissionRequest` 只表示工具申请权限，自动审查可以直接通过，不证明存在需要用户处理的窗口。移除该 Hook；已经加载的旧配置调用 `approval_needed` 时，新脚本同样静默退出。普通工具执行完成不再制造 `approval_resolved` 消息。
2. Hook 预先看到询问工具调用并不证明问题已发布。真实询问由 Codex 原生日志识别，异步请求必须收到 `accepted:true`；提醒必须有 session、turn、call 三个标识。
3. 启动时清理 `legacy:input` 等占位等待与旧通用审批。缓存活动先置为待核验的 idle，保留项目元数据；原生日志完整追平后的内部 `input_sync` 才恢复真实工作和待答状态。未读完大型日志不会发送空待答快照。
4. 待答计数逐项统计当前原生轮次的请求 ID；已回答、旧轮次、子 Agent、设置演示和被状态转换拒绝的消息不能产生新的实际待办或气泡。
5. 设置里的询问气泡预览只展示外观，不修改真实会话状态。项目面板说明改为实际待回答问题，工具授权仍在 Codex 原生面板处理。
6. 根据用户确认，重启前已经结束的轮次中的历史问题不再重建成当前待办。当前运行期间确认的问题，以及启动时仍在运行轮次中的问题，继续逐项提醒和解除。

## 保持的行为

- 真实问题显示约 8 秒后恢复其他动作，视觉提示结束不等于代替用户回答。
- 同一轮次多个问题各自等待对应回答，不由无关工具的完成事件解除。
- 当前运行期间任务成功完成但仍等待原生异步问题时，保留该真实待回答请求。
- 原生开始、暂停、成功、失败、额度耗尽及不同项目的工作计数继续使用实际生命周期记录，不按沉默时间推断结束。
- 托盘、设置的浅绿样式、模型、拖拽、工作流光、晕眩眼睛与视频项目没有更换。

## 历史问题规则与接口边界

本机复核确认过一条 10 月 4 日已结束会话中的原生异步问题。它有已发布记录，没有回答记录；接口不能证明该历史问题是否仍存在于当前 Codex 页面。用户随后明确选择“移出历史待办”。

最终使用进程内 `CurrentQuestionLedger` 区分当前问题与重启前已结束轮次的问题，不按问题年龄设置超时。旧问题从桌宠当前待办移出，原生会话日志与本轮修改前备份保留。

工具 Hook 仍不能可靠区分“自动允许”与“真实等待人工权限确认”。因此桌宠不再通过通用权限申请弹出人工操作气泡；真实询问继续提醒，权限确认仍由 Codex 原生界面处理。
